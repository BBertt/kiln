A Claude-style guide and design system for Kiln artifacts

Kiln gives agents almost no guidance on how to build an artifact, so every artifact looks different. This proposal adds a written guide like the one Claude follows, a shared design system based on Claude's look, Claude's typography, and light and dark themes on every artifact. It also shows how to collect Claude's design system from sources we can check.

Decisions needed from you

  1. Fonts. Claude's own fonts cannot be licensed. Approve the plan to name them first and ship free look-alikes. See Claude's font.
  2. Examples. Share two or three Claude artifacts you like, as published links or as code. They are the best evidence for the plan and progress style. See step 5 in How to collect it.
  3. Where the guide lives. Approve moving the guide into the MCP server so every agent receives it. See Changes to Kiln.

How to collect Claude's design system

Anthropic does not publish a single "artifact design system". Claude's look comes from three things: the claude.ai interface, the instructions Claude follows, and Claude's own design habits. I collect it from the sources below, most trustworthy first. Steps 1 to 4 are done. Step 5 needs you.

  1. Anthropic's public skillsDone

    The anthropics/skills repository is official and Apache 2.0 licensed, so Kiln may adapt it. Three skills matter:

    • brand-guidelines: the brand palette (dark #141413, light #faf9f5, clay #d97757) and stand-in fonts, Poppins for headings and Lora for body text.
    • frontend-design: design principles, and a list of habits that make a page look machine-made.
    • web-artifacts-builder: the artifact stack (React, Tailwind, shadcn/ui) and what to avoid: centered layouts, purple gradients, the same rounded corners everywhere, and the Inter font.
  2. Live claude.ai stylesDone

    I opened the logged-out claude.ai page in a headless browser and read its loaded fonts and CSS variables. It gave the font families and their fallbacks, the clay accent #d97757 and its stronger shade #c6613f, a base corner radius of 4px, and weights 400, 500, 580 and 600.

  3. A published Claude document artifactDone

    Public artifact links work without a login. On a published markdown artifact, headings use Anthropic Serif at 22, 18 and 16px, weight 600. Body text also uses the serif, at 15px with 21px line height. Code uses Anthropic Mono at 13.5px. Text is 90% black on white.

  4. Anthropic's showcase artifactsDone

    Anthropic hosts example artifacts at assets.claude.ai/brand/artifacts. The billing review example uses a serif title at 20px, weight 400, with slightly tight letter spacing. Tables use the sans at 13px, and column headers are 11px, weight 500, in #5e5d59. Text is #141413, the page is white, and corners are 6px.

    These examples name "Anthropic Serif" and "Anthropic Sans" but never load them. Visitors without the fonts installed see Georgia and system fonts.

  5. Your own Claude artifactsNeeds you

    This is the best source for the implementation plan and progress style you like. claude.ai needs your login, so I cannot open your chats. Two ways to share them:

    • Publish two or three artifacts from claude.ai and send the public links.
    • Or copy their code into a local folder outside this public repository.

    I then run the same browser probe on each one and list the patterns they repeat: layout, type sizes, colors, and components.

  6. Leaked system promptsRejected

    Copies of Claude's artifact instructions circulate online. They are unofficial and may be out of date. Copying them into a public repository is not a good idea. The guide uses Kiln's own facts instead.

The browser probe used in steps 2 to 5

It runs in the page and records what the browser actually rendered, not what the CSS files claim.

const fonts = [...document.fonts].filter(f => f.status === 'loaded').map(f => f.family);
const role = (sel) => {
  const el = document.querySelector(sel);
  const s = el && getComputedStyle(el);
  return s && [sel, s.fontFamily, s.fontSize, s.fontWeight, s.color].join(' | ');
};
const roles = ['h1', 'h2', 'p', 'th', 'td', 'code', 'button'].map(role);

Claude's font

You asked for Kiln to use Claude's font. claude.ai loads three fonts that Anthropic made for itself:

  • Anthropic Sans for the interface: buttons, menus and labels.
  • Anthropic Serif for headings, Claude's replies and document artifacts.
  • Anthropic Mono for code.

All three are variable fonts covering weights 300 to 800. The light serif over plain sans text is most of what makes Claude look like Claude.

We cannot ship these fonts. I found no public license for them, and font reference sites say they are not available to license. Kiln's repository and site are public, so adding the font files would redistribute them.

Linking to Anthropic's copies would technically work, because their font server allows any website. I don't recommend it. There is no license, the file names change when Anthropic deploys, and every visitor's browser would contact Anthropic.

Light and dark themes

Every artifact supports a light and a dark theme. By default it follows the reader's system setting. A switch lets the reader choose System, Light or Dark. This page has the switch in its top bar.

Kiln provides the switch, so artifacts don't build their own. Each artifact page gets a slim top bar with a link back to the gallery, the artifact title, and the theme switch. The browser saves the choice, and it applies to every artifact on the site.

A small script runs before the page appears. It reads the saved choice, checks the system setting, and marks the page as light or dark. This avoids a flash of the wrong theme. HTML artifacts get the same mark inside their frame. It updates at once when the reader switches, or when the system changes while "System" is selected.

Each color token holds both values. The CSS light-dark() function picks the right one for the current theme, and current versions of all major browsers support it. One extra Tailwind line makes dark: classes follow the switch, not only the system setting.

:root { color-scheme: light dark; --kiln-bg: light-dark(#faf9f5, #191919); }
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"]  { color-scheme: dark; }
@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));

What each artifact must do:

  • Take every color from the Kiln tokens or from Tailwind dark: classes. Hard-code a color only when it works on both backgrounds, such as a chart series.
  • Draw SVG lines and labels with currentColor or the tokens.
  • Give charts their colors from the tokens.
  • Keep text contrast at 4.5 to 1 in both themes.
  • Look at both themes before reporting the artifact as done.

The nine other artifacts in the gallery hard-code their colors. They will ignore the switch until they are rebuilt with the tokens.

Layout

Reading text sits in a column about 720px wide. Tables, diagrams and code may use the full 1080px. Text is left aligned. Corners are 6px on cards and tables, 4px on small controls, and fully round only on status pills.

Components for plans and progress reports

Status

  • Status pill: Done, In progress, Blocked, Not started.
  • Status line under the title: state and date.
  • Progress: steps done out of total, with a thin bar.

Structure

  • Step list, numbered only when the steps are a real sequence.
  • Decision box with the questions for the reader.
  • Risk table and a sources list at the end.
  • Collapsible technical detail.

Rules

Do

  • Put the status and the decisions on the first screen.
  • Use sentence case for every label.
  • Keep text contrast at 4.5 to 1 or higher.
  • Label every control and keep focus visible.
  • Animate only in response to an action, and respect reduced motion.

Avoid

  • All-caps labels above every heading.
  • Purple gradients, Inter, and centered body text.
  • The same rounded card for every block.
  • Clay on more than one job.
  • Entrance animations on every section.

Anthropic's frontend-design skill calls this cream, serif and clay look "Anthropic's own Claude-interaction accent" and warns against it as a default for other brands. Here you asked for exactly that look, so it becomes Kiln's house style. An artifact should still switch style when its user asks for a different look.

The authoring guide

The guide follows the shape of Claude's artifact instructions, but every rule comes from what Kiln actually supports. It has eight parts:

  1. When to make an artifact. Substantial, self-contained content the user will read again or share. Short answers stay in chat.
  2. Which format. HTML for documents, plans and reports. React for interactive tools. Vue or Svelte only when asked.
  3. What is available. Tailwind, the Kiln theme tokens and font classes, lucide-react, recharts and framer-motion. No backend.
  4. Runtime limits. HTML runs in an iframe with scripts on. All artifacts share one website, so prefix any browser storage key with the slug. Never store private data.
  5. Design. The design system above, with the do and avoid lists. Every color comes from the tokens so both themes work.
  6. Document templates. Section order for an implementation plan and for a progress report, shown below.
  7. Edit or create. Reuse the slug for edits. Send the full code each time; each change becomes a new revision.
  8. Check before reporting. Open the preview in both themes, try every control, give both links, and wait for GitHub Actions before saying the site is live.

Implementation plan template

  1. Title and status line
  2. Summary: what changes and why, in three sentences
  3. Decisions needed

Changes to Kiln

The guide should live in one file and reach every agent through the MCP server. The installed MCP SDK supports server instructions, resources and prompts.

FileChange
src/guide/authoring.mdNew. The full guide, the single source of truth.
src/tools/mcp-server.tsSend short server instructions on connect. Serve the full guide as a resource. Add plan and progress prompts. Point the tool description at the guide.
src/layouts/ArtifactLayout.astroAdd the slim top bar with the gallery link, title and theme switch. Add the script that sets the theme before the page appears.
src/pages/artifacts/[...path].astroPass the theme into each HTML artifact's frame, and update it when the reader switches.
src/styles/artifact.cssAdd the tokens with light and dark values, the font stacks, and the Tailwind dark: rule as a Tailwind theme. Artifacts can then use classes like font-serif and text-kiln-muted. HTML artifacts already receive these styles. Theme the loading and error screens too.
src/styles/gallery.cssReplace Inter with the same font stacks. Use the same tokens and theme switch, so the gallery matches the artifacts.
package.jsonAdd the three @fontsource-variable packages.
AGENTS.mdLink to the guide instead of repeating it.
artifacts/Two reference artifacts, a plan and a progress report, built with the system.

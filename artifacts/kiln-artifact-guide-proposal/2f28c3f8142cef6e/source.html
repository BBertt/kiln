A Claude-style guide and design system for Kiln artifacts

Kiln gives agents almost no guidance, so every artifact looks different. This proposal adds a written guide like the one Claude follows, a shared design system, Claude's typography, and light and dark themes on every artifact. This revision is based on two real Claude artifacts you shared.

Decisions 3 open, 1 settled

D1. Which fonts should Kiln use?
Needs you

Claude's own fonts cannot be licensed. Your two references don't use them either: they use a sans font for everything and a mono font for labels.

Recommended: Name Claude's fonts first, then ship free look-alikes. Hanken Grotesk for text and headings, JetBrains Mono for labels and code, and Source Serif 4 for long reading pieces.
D2. May an artifact use its subject's own colors and fonts?
Needs you

Your tracker reference uses its project's brand colors and fonts, not Claude's. The report reference uses neutral grays.

Recommended: Yes. Kiln's palette and fonts are the default. An artifact may replace the values when its subject has a brand, if it keeps the token names and gives a dark value for each one.
D3. Where should the guide live?
Needs you

Today only agents working inside the Kiln folder see any guidance.

Recommended: In the MCP server, as instructions sent on connect plus a full guide agents can read. See Changes to Kiln.
D4. Light and dark themes on every artifact?
Settled
Decided: yes. The system theme is the default, and the reader can switch (10 Nov).

What they share

  1. Color tokens at the top. Background, surface, line, text, muted, an accent with a soft wash, and status colors that each have a matching wash. Every token has a light and a dark value.
  2. One theme convention. The system setting decides by default, and a data-theme mark on the page overrides it. Neither artifact draws its own switch.
  3. One column, most useful content first. The tracker even states its layout plan in a comment at the top of its styles.
  4. One sans family plus mono. Mono carries metadata: links, dates, counts, IDs and status pills.
  5. Status as small pills. Colored text with a dot, on a matching wash.
  6. Counts next to section titles, such as "0 open, 8 settled" or "6 of 8 phases on staging".
  7. Data apart from layout. Content sits in one list, and a script draws it. The script uses plain text, never raw HTML, and only allows https links.
  8. Loading, empty and failed states with a sentence explaining what will appear.
  9. Accessibility basics. Labelled sections, pressed states on filter buttons, labelled progress bars, visible focus, and motion only when the reader allows it.
  10. The reader's language. The report is written in Indonesian and says so in its lang attribute.

Neither artifact uses Claude's fonts or the cream and clay palette. Claude's artifact look is a structure and a token discipline, not a fixed palette. So Kiln should fix the structure and the theme convention, and supply a default palette and fonts that an artifact may replace.

Parts worth reusing

Now panel

Three columns: working on, next, waiting on you. The waiting column turns red when something needs the reader.

Decision card

Question, context, options, a recommended answer on a tinted box, then "Decided: …" with a date. Open ones first.

Phase timeline

A rail of short phase codes joined by a line. Each phase has a title, a status pill, a summary, links and its dependencies.

Step checklist

A progress bar, then collapsible steps. Done steps are struck through. Active phases open by default.

Log

Newest first. A date column in mono, then the phase code and one line of what happened.

Summary and stat cards

Key and value pairs for each option, then small cards for the winners, with a label, a value and a note.

Results table

Scrolls sideways on phones, with sticky headers, tier badges, score colors, aligned numbers and filter buttons.

Callout and sources

A tinted note with an accent edge for caveats. A numbered source list and a dated footer at the end.

Claude's font

claude.ai uses three fonts Anthropic made for itself: Anthropic Sans for the interface, Anthropic Serif for headings and Claude's replies, and Anthropic Mono for code. I found no public license for them, and font reference sites say they are not available to license. Kiln is public, so shipping the files would redistribute them. Linking to Anthropic's copies would technically work, but it has no license, the links change when Anthropic deploys, and visitors' browsers would contact Anthropic.

Your references point the same way as the license: Claude's code artifacts use a plain sans and a mono, not Anthropic's fonts. So Kiln names Claude's fonts first, which helps only on a device that has them installed, and ships free look-alikes for everyone else.

--font-sans:  "Anthropic Sans", "Hanken Grotesk", system-ui, sans-serif;
--font-mono:  "Anthropic Mono", "JetBrains Mono", ui-monospace, monospace;
--font-serif: "Anthropic Serif", "Source Serif 4", Georgia, serif;  /* long reading only */

Kiln would bundle the free fonts from the @fontsource-variable npm packages, under the SIL Open Font License, so no font service is called. This preview loads them from Google Fonts only for the comparison.

Layout and shape

One column, 920 to 1100px wide, with 48px between sections. Prose stays near 68 characters a line. Corners are 16 to 20px on large panels, 10 to 12px on cards and tables, and fully round on pills. Section order puts what the reader must act on first.

Light and dark themes

Every artifact supports both themes, follows the system setting by default, and lets the reader choose System, Light or Dark. Kiln draws the switch in a slim top bar on each artifact page, next to a gallery link and the title. The browser saves the choice for every artifact on the site. This page has the same switch in its top bar.

Kiln uses the same convention as your references, so artifacts Claude writes work in Kiln unchanged. A script sets data-theme="light" or "dark" on the artifact before it appears. Without the mark, the artifact still follows the system.

:root { --kiln-bg: #faf9f5; /* light values */ }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --kiln-bg: #191919; color-scheme: dark; }
}
:root[data-theme="dark"] { --kiln-bg: #191919; color-scheme: dark; }
@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));  /* Tailwind */

What each artifact must do:

  • Take every color from the tokens or from Tailwind dark: classes, and give every token a dark value.
  • Never draw its own theme switch.
  • Draw SVG lines and labels with currentColor or the tokens, and give charts token colors.
  • Keep text contrast at 4.5 to 1 in both themes, and check both before reporting.

The nine older artifacts in the gallery hard-code their colors and will ignore the switch until they are rebuilt.

Rules

Do

  • Put status, counts and decisions on the first screen.
  • Keep data in one list and draw it with a script, using plain text and https links only.
  • Write empty, loading and failed states.
  • Write in the reader's language and set lang.
  • Label every control, keep focus visible, respect reduced motion.

Avoid

  • Hard-coded colors outside the token block.
  • Purple gradients and centered body text.
  • The same card for every block.
  • The accent on more than one job.
  • Entrance animations on every section.

The authoring guide

The guide follows the shape of Claude's artifact instructions, but every rule comes from what Kiln supports. It has eight parts:

  1. When to make an artifact. Substantial content the reader will return to or share. Short answers stay in chat.
  2. Which format. HTML for trackers, plans and reports. React for interactive tools. Vue or Svelte only when asked.
  3. What is available. Tailwind, the Kiln tokens and fonts, lucide-react, recharts and framer-motion. No backend.
  4. Runtime limits. HTML runs in a frame with scripts on. All artifacts share one website, so prefix storage keys with the slug and never store private data.
  5. Design. The tokens, theme convention, type, layout and rules above.
  6. Templates. A work tracker and a findings report, below.
  7. Edit or create. Reuse the slug for edits and send the full code. Each change becomes a new revision.
  8. Check before reporting. Open the preview in both themes, try every control, give both links, and wait for GitHub Actions before saying the site is live.

Work tracker: plans and progress

  1. Header: links to the issue and design in mono, the update time, a title, one sentence on what the page tracks
  2. Now: working on, next, waiting on you
  3. Decisions with a count: open first, each with a recommendation
  4. Work sequence with a count: phases in shipping order, each with steps
  5. Log, newest first
  6. Footer: who updates the page

Findings report: tests, comparisons, spikes

  1. Header: title, one sentence, chips for date, version and sample size
  2. Summary: one card per option, then stat cards for the winners
  3. Main results table with filters
  4. What could not be tested
  5. Recommendation
  6. Alternatives and why they lost
  7. Method and limits
  8. Sources and a dated footer

Your tracker updates itself from Claude's built-in artifact storage. Kiln has no storage, so a Kiln tracker keeps its data in the page and the agent republishes it. Each update then becomes a revision you can go back to.

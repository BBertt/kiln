What the adapter has to do

  1. Call the image endpoint. litellm.aimage_generation(model='openai/dola-seedream-5-0-flash-260915', api_base=…, api_key=…). The chat call shape cannot reach ModelArk.
  2. Turn the aspect ratio into pixels. Seedream takes size='WxH'; every ratio the plan step offers maps to a size between 921,600 and 4,624,220 total pixels. All seven came back exactly as asked.
  3. Send Seedream's options in extra_body. watermark and response_format are rejected as plain arguments, so they go in extra_body.
  4. Never send the ratio as image_config. The call succeeds but the ratio is not honoured: a 4:5 request returned 1664×2496 (2:3). Only size is honoured.
  5. Ask for base64. The default is a 24-hour signed URL; response_format='b64_json' returns the JPEG inline, 396 to 600 kB.
  6. Widen the refusal test. Production recognises SensitiveContentDetected. ModelArk says may be related to copyright restrictions for a real person and may contain sensitive information for violence, both as a 400.
  7. Register the per-image price. Register input_cost_per_image under the model id and LiteLLM returns it as response_cost. The spike's first pass used output_cost_per_image, which the image calculator ignores; a local test with the correct field reports $0.018.

Cost correction. The spike's first pass registered output_cost_per_image, so response_cost stayed None. LiteLLM's OpenAI-style image calculator reads input_cost_per_image; registered that way, the same call reports $0.018. Verified locally against a synthetic image response, not re-run against ModelArk.

What this does not answer

  • Seedream 5.0 Pro is slower than production's timeout. It answered in 39 and 45 seconds; the worker gives a provider 30. On the previous account key it hung twice past 90 s, so its availability is account-dependent.
  • Image-to-image, layer decomposition, sequential batches. Our worker generates one text-to-image per slot; the rest is out of scope.
  • Quality. This spike measures plumbing, latency and cost. Which image model looks better is a separate comparison.
  • Throughput. Seventeen sequential images prove the route; they do not set a rate limit or a concurrency budget.

Recommendation

Switch the image worker to aimage_generation on openai/… with ModelArk's base URL. It needs no new dependency, the price matches today's OpenRouter route ($0.018 an image), and one image takes 14 to 21 seconds, inside the 30-second provider timeout. Keep OpenRouter configured as the fallback until a production canary has run. Seedream 5.0 Pro is reachable but takes 39 to 45 seconds and costs $0.045 to $0.09 an image, so choosing it means raising that timeout.

Method

The spike script calls ModelArk once per case with the pinned LiteLLM version the API ships, the repo-root provider key and no retries. It records the exception class and HTTP status for every failure, the response carrier and byte size for every image, and LiteLLM's reported cost. Image dimensions are read back from the returned bytes.

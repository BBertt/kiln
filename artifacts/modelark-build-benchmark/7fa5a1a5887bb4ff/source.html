Recommendation

The four models that never built a site

Neither GLM nor Seed could drive our tools, and both failures are argument-shape mismatches rather than bad code:

  • GLM 5.2 and GLM 5.3 Flash called create_plan every time, but sent the nested plan value as a JSON string. Our schema expects an object, so every plan was rejected three times and the turn ended. The string parses as JSON in the log, so the content was there.
  • Seed 2.0 Pro and Dola Seed 2.1 Turbo got past the plan and then sent write_files with empty arguments ({}), and their write was cut off at the model's output limit. Retrying produced the same empty call.

A tolerant parser that json-loads a string where an object is expected, and a smaller write payload, would likely rescue both families. That change is untested here and was not made mid-benchmark, because it would have given those models a pipeline the other three never got.

What this does not test

  • Behaviour after the build. Does a checkout really save an order? The harness checks structure, not journeys. The reviewers read the code for faked writes and leftover template scaffolding.
  • Long conversations. Every build is a first build. Edit turns and follow-ups are not measured.
  • Admin screens. The admin captures show only the login page (the harness does not sign in), so admin CRUD was judged from source.
  • Images. Every build starts from the same six pre-generated photographs, so this measures image placement, not the plan's picture choices.
  • Provider throughput. Two to four builds ran at once on one account; that is not a rate-limit test.

Method

Each build ran the production pipeline through the eval harness: the plan step and the write step used the model under test, while the safety classifier, the module picker, the design lookup and the image model stayed as production keeps them. Fallbacks were switched off, so a model that failed could not finish on another model's work. Repair rounds stayed on, as in production.

Every build ran in Docker from its template's app-base image with PocketBase live; Playwright then loaded each route, scrolled it, waited for images, and screenshotted it. The briefs are the harness's canonical fixtures with one change: each lists the six shared image URLs, so every model had the same pictures.

Reproduce: uv run python scripts/benchmark/02_run.py, then 03_score.py and 04_review.py.

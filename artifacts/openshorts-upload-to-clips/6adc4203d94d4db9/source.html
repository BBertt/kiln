OpenShorts · Pipeline explained

One upload.
Several short, vertical clips.

OpenShorts finds useful moments in your existing footage. It does not generate replacement footage for the uploaded-video clipping workflow.

The main idea: Speech becomes timestamped text. An AI chooses moments from that text. Local video tools cut, reframe and caption the selected moments. Optional visual checks also call an AI service.
  1. Backend

    Upload the source and start a job

    The dashboard sends your file to the backend in app.py. The backend saves it and launches main.py as a separate process.

    Your choices travel with the job: target clip count, clip length, output format, layout, hook text and captions. Clip counts are targets, not guarantees.

  2. Optional AI vision

    Check the source’s visual layout

    If automatic layout is enabled, the service sends 12 sampled frames to Gemini. It uses the answer to enable suitable layouts, such as a screen recording or stacked speakers.

    When captions are enabled, a separate visual check can detect subtitles already burned into a horizontal source. The renderer can trim that subtitle band to avoid duplicate text.

    These checks run before clip rendering. Sources already in the target vertical shape skip these layout and subtitle-band checks.

  3. Local speech recognition

    Turn speech into timestamped text

    Whisper transcribes the audio locally. It records what people say and the start and end time of each word. The service saves a checkpoint so an interrupted run can reuse the transcript.

    If there is little or no speech: the job takes a different route. Gemini analyzes video segments and picks moments from the imagery. This path needs Gemini and has no speech captions to add.
  4. AI text analysis

    Choose the strongest moments in two passes

    Pass 1: score the whole transcript

    The code divides the transcript into windows, normally around 90 seconds. Longer requested clips use larger windows. The AI scores each window for its potential as a short clip.

    The service keeps the highest-scoring windows for closer review. The shortlist target grows with source length, from 3 to 10 windows when enough windows exist.

    Pass 2: select exact clips

    The AI receives the shortlisted text and returns clip start and end times, a score, a YouTube title, TikTok and Instagram descriptions, and a short hook line.

    The default length range is 15–60 seconds. If the AI returns fewer clips than requested, the code can ask again using shortlisted windows it has not used.

    Clean up the selections

    The code adjusts cuts to word boundaries and removes clips that overlap a better-scored selection. It saves clip details and the transcript in a metadata file.

    This stage uses Gemini by default. Setting LLM_BASE_URL routes these text calls to an OpenAI-compatible model instead, such as a compatible BytePlus Seed endpoint.

  5. Local video processing

    Cut and reframe each selected moment

    FFmpeg cuts the selected timestamps from the original source. The renderer then detects scene changes and analyzes faces to choose how each scene fits the output frame.

    Framing depends on the scene and enabled layouts.
    ModeWhat the viewer sees
    TRACKA vertical crop follows a face. Smoothed camera movement avoids sudden jumps.
    GENERALThe wide shot stays visible, with a blurred background filling the vertical frame. This suits groups or scenes without faces.
    SPLITTwo speakers appear stacked when the layout is enabled and the scene qualifies.
    SCREENCASTScreen content and the presenter get a suitable layout when that feature is enabled.

    MediaPipe and YOLO handle local face and person detection. The default renderer analyzes smaller frames, then asks FFmpeg to render the crop at output resolution with the source audio.

    Multiple clips can render at once, with up to six workers by default. Higher-scored clips enter the render queue first.

  6. Finishing and delivery

    Add text layers and show the results

    If enabled, the renderer burns the hook line into the clip. When visual content carries the meaning, an additional Gemini check can rewrite the hook and title using frames from the rendered clip.

    Captions use the existing word timestamps, so the service does not need to transcribe every clip again. In stacked layouts, captions can sit along the seam between speakers.

    The free hosted plan adds a watermark. Self-hosted runs have no plan watermark.

    The backend announces each completed clip. The dashboard checks job status and shows finished clips before the whole batch completes. You can then edit, recut, download or publish them.

What a BytePlus switch would change: Seed would replace the AI decisions, not FFmpeg, transcription or face tracking. The transcript picker already supports compatible endpoints. Gemini-based visual checks need code changes. Seedance video generation is not needed for cutting clips from uploaded footage.

This explanation follows the inspected repository code, not a completed processing run. No OpenShorts code was changed.
